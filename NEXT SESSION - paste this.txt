Alexandra asked for five things on 2026-10-02 (⚠️ **relayed by Graeme, never confirmed with her
directly** — treat as her requirements as he understands them). Phase A is the first two of them:

**(1) An optional box under the learning objective — "What should pupils actually do on this
worksheet?"** — so she states the task instead of the app inferring it from the curriculum
objective alone.

**(3) A section asking what is getting in the way** — decoding · vocabulary/limited English ·
reading comprehension · forming sentences · writing a lot · remembering instructions · working
independently — *"so the site removes the actual barrier rather than just making the work easier."*

The plan's Phase A section has the full design. The parts that will cost you a day if you miss them:

🚨 **1. `SOURCE_LAW` MUST STAY THE FINAL BLOCK IN THE PROMPT. This killed the first draft of the
plan.** The order is:

    [source opening] → [base template] → [task] → [barriers] → [source_instructions]

Her one hard constraint is *"if I upload only part of a story, only use what I've supplied and do
not reveal later parts"*, and it is defended by `SOURCE_LAW` sitting last (measured 2026-09-15).
Put the task block after it and a box saying *"write the next chapter"* outranks it. Her **primary
English route is a scan of book pages, where the name check cannot run at all**
(`planning/source_names.py:561-570` returns `names_checked=False` for a non-held source) — so on
that route the ordering is the only defence there is. Add the test:
`prompt.rindex(SOURCE_LAW) > prompt.rindex(<new marker>)`, per type × action.

⚠️ **2. One load-bearing edit**: `llm/prompts.py:1559-1560` returns `base` early when there is no
source. That must become a fall-through, or **a task typed with no upload is silently dropped.**

🚨 **3. The task must not override the `DIFFERENTIATION LEVEL RULES` block.** The three API calls
differ *only* by `level`. Let a task fix question count or length and the three sheets collapse
into one sheet at three font sizes — **and she pays for three.** Nothing in the suite compares the
three sheets to each other; add that. ⚠️ And note the trap the premortem found: a test built on
`a_sheet()` from `tests/test_worksheet_typography.py:54-105` renders **one fixed content set** three
times, so it cannot see three API calls that returned the same content. Count questions in the
returned JSON, not in the render.

🚨 **4. "Writing at length" is NOT free on every type — measured by rendering, not grepping.**
Only six of the ten answer-line sites read `q.get('lines', N)`. `investigation.py:112` and `:253`
hard-code `num_lines = 3 if is_dev else 2`. `cloze`, `word_bank` and `times_tables` have **no
answer lines of their own at all** — their only ruled lines are the EAL glossary's four, which is a
*support* and may not be shrunk. **So the plan's headline behavioural test will fail on four types
after the feature is built correctly.** Scope it to an allow-list with a companion asserting the
other four are byte-identical, and ⚠️ **do not soften `<` to `<=`** — that makes it pass vacuously,
which is the empty-haystack-reports-green failure this project is built against.

⚠️ **5. The barrier seam misses the lesson page.** `with_the_barriers_answered` goes beside
`with_the_source_in_place` at `app.py:1325` — but `pages/2_Lesson_Plans.py:697` →
`planning/worksheet.py:917` → `build_worksheet_document` at `:778` is a **second, independent
path that prints the sheets handed to children as a lesson's evidence**, and never crosses that
seam. Either put the seam where both paths cross, or state the scope **and print it on the lesson
page** — silence there is the "nothing changes silently" failure.

🚨 **6. The privacy wording is not cosmetic.** Her phrasing was *"what does this **pupil**/group
need help with?"* — the word *pupil* invites a name into a box sent to Anthropic, and
`pages/2_Lesson_Plans.py:1074-1079` already records that a free-text need box *"predictably attracts
pupil names, and 'we did not ask for them' is not a control."* So: the heading asks about the work
— **"What is getting in the way?"** — seven tick-boxes held as a **dict** (keys drive render
decisions, labels are hers), **no free-text box in this slice**, and an expander showing the literal
block that will be sent, rendered from the same function that builds it. Seven checkboxes means what
leaves the building is one of 128 possible strings; that is a real privacy claim and a checkable one.

⚠️ **7. Add the task to the name check's `approved` tuple** (`app.py:1340-1344`). Forget it and
every sheet warns about her own wording, she learns to ignore the warnings, and the next real
spoiler walks through. Build the mutation that proves it.

⚠️ **8. Four of seven barriers have a real printed consequence in this slice; three do not**
(forming a sentence · remembering instructions · working independently — all three need the worked
example or chunking, which do not exist anywhere in the repo). **The screen must not imply all seven
are handled.** Say per ticked barrier whether *this sheet type* can carry it — `source_panel`'s own
idiom of saying out loud what a type cannot do rather than hiding the control.

**Mechanics:** new `support_panel.py` at repo root (precedent `access.py`, `source_panel.py`),
namespaced `ws_*` keys · prompt wording in `llm/prompts.py` beside `source_instructions`, appended
after `.format()` so a brace in her text cannot break a template · new
`planning/support.py::with_the_barriers_answered(content, worksheet_type, barriers)` editing the
already-returned JSON, so it costs no tokens · **eight surgical edits in `app.py`**, listed in the
plan.

🔑 **The barrier transform works at all because four renderers are data-gated, not level-gated**
(`components.py:427`, `fraction_practice.py:200`, `calculation_practice.py:153`,
`reading_comprehension.py:79`), and `components.py:372` is dead code. That is the architectural core
— a deterministic transform on the JSON produces real printed consequences with no generator change.

**AS BUILT (2026-10-02), where it departs from the design above — each one measured:**

- **Word meanings contradicted the level rules.** Cloze and word-bank level rules say an expected
  sheet's words carry no `definition`; the limited-English line asks for one. The barrier footer
  now says a line asking for MORE support wins, and nothing may make a sheet harder.
- **Questions are cut by a fixed two (never below three), not a fraction.** Templates ask 4–5 /
  6–8 / 8–10 by level; a third off turned a 5- and a 6-question sheet into 4 each.
  `test_a_longer_sheet_still_ends_up_longer` caught it.
- **"Writing a lot" halves each writing space (never below one line) and keeps the task.** The
  plan said drop challenge/bonus/extension; that is making the work easier, which she said she does
  not want, and dropping the times-tables speed challenge contradicted the "four types unchanged"
  finding.
- **Comprehension = fewer questions on the two question sheets only;** asked-only elsewhere.
- **Lesson page: scope stated, not wired.** It prints `NOT_ON_THIS_PAGE`. Wiring it means the
  orphaned-evidence trap the plan records under Phase C.
- **The barrier seam runs after `with_the_source_in_place` and before `with_the_names_checked`,**
  so the name check reads the sheet as printed.
- **Matching and sentence-builder sheets shuffle on purpose** — any test comparing two renders must
  seed `random`, or it measures the shuffle.
- **`mutate.py` took any line starting "ERROR" as a broken file**, and Streamlit logs one. It threw
  away two real catches. Fixed with a positive control.

- **TDD genuinely.** Failing test first, confirm it fails FOR THE REASON YOU EXPECT, then
  implement. Then add a mutation to `scripts/mutate.py` for every guard and prove it is caught.
  **A mutation nothing catches is the finding.** Nine tests in the source feature were passing for
  the wrong reason and the mutation runner found all nine; it found two more disarmed guards on
  2026-09-22. Expect this.
- ⚠️ **A full `scripts/mutate.py` run is 9–10 hours** — 136 mutations at about 4 minutes each,
  measured. The `~2 hours` comment at `scripts/mutate.py:906` is stale and wrong. Use filtered runs
  (`mutate.py <substring>` matches label or file) while building, and one full run before a push.
  ⚠️ It edits files on disk and restores them in a `finally`, so **SIGINT, never SIGTERM** — and
  checksum the files it names before starting if you intend to interrupt it.
- ⚠️ **Run the suite with nothing else running.** The Streamlit `AppTest` tests time out at 30
  seconds under load and the failures look real.
- **A test cannot see a prompt defect.** **Fifteen of fifteen** defects in this repo were found only
  by running the real API. `scripts/live_run.py` writes every request, schema and raw reply to
  `live-runs/<timestamp>/` BEFORE parsing. ⚠️ A clean live run reads no refusal, so it verifies
  nothing about one — **when the thing you changed only fires on failure, cause the failure.**
- ✅ **The ten prompts are now pinned** — `tests/prompts_as_they_were/<type>.txt`, compared byte for
  byte. If a template legitimately changes, read the diff the test prints, then regenerate with
  `.venv/bin/python tests/test_prompts_as_they_were.py --rewrite` (needs
  `PYTHONPATH=<repo>`). **Never regenerate without reading the diff** — that defeats the file.
- **`app.py` stays structurally untouched.** No refactor; it has almost no coverage and it works.
  ⚠️ `GENERATOR_MAP` at `app.py:784` is parsed as text by TWO tests — a regex one
  (`tests/test_worksheet_document.py`) and an `ast` one (`tests/test_smoke.py`) — so its literal
  shape must not change. ⚠️ `tests/test_source_panel.py` slices the generation block between the
  sentinel strings `if generate_btn or _regenerating:` and `# Phase 2`; both are load-bearing.
  ⚠️ `tests/test_access.py:124` asserts three exact source strings appear in `app.py`.
- ⚠️ **The replay-tape test will fail while you implement, and that is it working.**
  `tests/test_source_panel.py:473-520` asserts everything read back from `generation_params` was
  written into it. Add the read first, watch it fail, then add the key.
- **A guard that refuses correct work is worse than no guard** — invisible on a green suite, and it
  surfaces as the teacher being told her correct work is wrong. But make a wrong guard RIGHT, never
  soften it. ⚠️ **And a guard can be wrong by being too LOOSE, which is worse**: a refusal is
  visible and gets a second attempt, a false pass hands a child a sheet that proves nothing.
- **A refusal the model will read is an instruction, not a description.**
- **Deterministic checks only. No AI judging AI.**
- **Nothing changes silently.** She is shown what the app did and why.
- **Verify a claim against the code before repeating it**, including claims in this file. The
  adversarial pass on 2026-10-02 found seven surviving objections, two fatal, in a plan written the
